# Как работать с репозиторием

Здесь описано, что настроено и как это включить у себя. Сами правила кода
(типы, докстринги, 90 символов) лежат в [AGENTS.md](AGENTS.md): они
одинаковы для людей и для ИИ-ассистентов.

## Первый запуск

1. Подними окружение проекта так, чтобы в корне появился `.venv`: на него
   смотрят редакторы и basedpyright.
2. Открой проект в редакторе из таблицы ниже.

## Редакторы

Правила хранятся в `pyproject.toml` и `.editorconfig`, то есть не в
настройках редактора. Нужно только подключить сами инструменты.

| Редактор | Что сделать |
| --- | --- |
| VS Code | Согласись на рекомендованные расширения (basedpyright, ruff). Остальное лежит в `.vscode/`. |
| Neovim | LSP `basedpyright` и `ruff`; форматирование через `ruff format` (например, conform.nvim). `.editorconfig` Neovim читает сам. |
| PyCharm | Плагины Ruff и BasedPyright; интерпретатор `.venv`. `.editorconfig` читается из коробки. |

Если подсказки по типам или докстринги не показываются, проверь, что
редактор видит интерпретатор `.venv`.

## Ручной запуск проверок

```sh
ruff format
ruff check --fix
basedpyright
```

Запускай все три перед каждым коммитом.

## Что проверяется

| Требование | Чем проверяется |
| --- | --- |
| Строка не длиннее 90 символов | ruff (E501, W505), `ruff format` |
| Единый формат кода | `ruff format` |
| Типы у параметров и возвращаемых значений | ruff (ANN), basedpyright |
| Докстринг у публичных классов, функций, методов | ruff (D) |
| Докстринги у приватных функций, констант и полей класса | **проверяется на ревью** |

Последняя строка таблицы автоматически не проверяется: ruff и basedpyright
этого не ловят. Смотрим глазами при ревью.

## Если пишешь код с помощью ИИ

Ассистенты читают `AGENTS.md` автоматически (для Claude Code и Gemini CLI
есть `CLAUDE.md` и `GEMINI.md`). Если твой инструмент так не делает,
вставь ему `AGENTS.md` в начале сессии. Ответственность за результат
твоя: проверки должны проходить, а код нужно понимать до коммита.

## Если правило мешает

Не обходи его через `# noqa` или `# type: ignore` без причины. Если
правило действительно не подходит проекту, предложи изменить
`pyproject.toml` отдельным PR и объясни почему.
